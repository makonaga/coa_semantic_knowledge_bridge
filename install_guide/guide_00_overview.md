# ガイド00: 全体像とリージョン選択

AWS Context Ontology Accelerator(COA)v0.1.0 を自分の AWS アカウントにセルフホストし、
RAG(ベクター検索)を置き換える「オントロジー+GraphRAG」ナレッジ基盤として、
Web UI・REST API・MCP の3経路から使えるようにするためのガイドです。

本ガイドの手順は、実際に COA v0.1.0 をオレゴンリージョンに構築し、
テストデータ投入 → 3層すべての回答検証 → MCP 接続までを完走した実測記録
(`docs/build-log/`)に基づいています。

## COA とは

COA は AWS が公開しているソリューション実装
([aws/context-ontology-accelerator](https://github.com/aws/context-ontology-accelerator)、Apache-2.0)で、
構造化データ(Glue テーブル)と文書を「オントロジー(知識の骨格)+ナレッジグラフ+ベクター索引」
として統合し、質問を次の3層カスケードで解決します。

| Tier | 解決方法 | 特徴 |
|---|---|---|
| Tier 1 | メトリクスの完全一致(名前/同義語) | LLM に SQL を書かせない**確定的実行**。confidence 100% |
| Tier 2 | 自然言語 → SQL(または SPARQL → Ontop/R2RML → SQL) | 承認済み FK・スキーマ知識を使った集計・結合 |
| Tier 3 | GraphRAG(ベクター検索+グラフ探索+回答合成) | 文書にしか無い知識(規程・ノウハウ)への回答 |

通常の RAG と違い、「どのテーブル・カラム・関係を使ってよいか」を人間が承認した
オントロジーが土台になるため、集計値は SQL で正確に返り、権限(見せてよい列・テーブル)も
利用者ごとに制御されます(詳細は [ガイド06](guide_06_application_integration.md))。

## アーキテクチャ概要

デプロイすると CDK スタック **16個**(メインリージョン15個 + us-east-1 に CloudFront 用 WAF 1個)が作成されます。

- **入口**: CloudFront + S3 の Web UI(管理・Playground)/ AgentCore Runtime の HTTPS エンドポイント(API・MCP)
- **認証**: Cognito ユーザープール(外部 OIDC/SAML IdP のフェデレーションにも対応)
- **推論**: Bedrock(Claude 系 LLM + 埋め込みモデル)、AgentCore Runtime 上の
  Context Manager(質問応答)と MCP サーバー(エージェント連携、6ツール)
- **知識ストア**: Neptune(ナレッジグラフ)、OpenSearch Serverless(ベクター索引)、
  DynamoDB(メタデータ・権限)、Glue/Athena(構造化データ)
- **パイプライン**: Step Functions + ECS(スキャン、文書取り込み、オントロジー生成、削除)

## リージョンの選択(オレゴン / 東京)

メインリージョンは環境変数 `COA_REGION` で切り替えます。本ガイドは両リージョンを想定しています。

| リージョン | 位置づけ |
|---|---|
| **オレゴン(us-west-2)** | **本ガイドの実証済み構成**。所要時間・コストの実測値はすべてこのリージョンのもの |
| **東京(ap-northeast-1)** | 構築可能な想定だが、**下の3点を必ず事前確認**してから着手する |

> **注意**: CloudFront 用 WAF スタック(`coa-dev-edge-waf`)は AWS の仕様上、
> どちらを選んでも **us-east-1 に作成されます**。CDK bootstrap が両リージョンに必要です。

### 東京リージョンの事前確認3点(コマンドは [ガイド01](guide_01_prerequisites.md) に掲載)

1. **Bedrock AgentCore の提供状況** — AgentCore は東京で提供済み(2025年10月 GA 時点)ですが、
   組織のアカウント設定によっては使えないことがあるため、実際に API を呼んで確認します。
2. **Claude モデルの推論プロファイル** — COA は `us.` プレフィックスのクロスリージョン
   推論プロファイルをハードコードしており、**これは米国リージョン専用**です。東京では
   `jp.`(国内完結)または `global.` / `apac.` プレフィックスのプロファイル ID に
   置き換えるパッチが必要です([ガイド02 ステップ4](guide_02_deployment.md))。
3. **埋め込みモデルの提供状況** — `amazon.titan-embed-text-v2:0` が東京で呼べるかを
   実呼び出しで確認します。呼べない場合の選択肢は「Cohere Embed v4 を使う(組織の
   利用承認が必要な場合あり)」「オレゴンに構築する」の2つです
   (埋め込みモデルにはクロスリージョン推論プロファイルがありません)。

## コスト概要(オレゴン実測)

| 状態 | コスト | 内訳の主役 |
|---|---|---|
| フル稼働 | 約 $1.9/時(約 $45/日) | Neptune(db.r6g.large)、ECS、NAT |
| 停止運用時(`stop-coa.sh` 実行後) | **約 $0.44/時(約 $10.6/日)** | VPC エンドポイント約40本 + NAT |
| デプロイ所要時間 | 約 62 分 | — |

- 本リポジトリのパッチで Neptune を `db.r8g.large` → `db.r6g.large` に縮小しています
  (これ未満はナレッジグラフ構築でメモリ不足になるため下限。詳細は [ガイド07](guide_07_troubleshooting.md))。
- **アイドルでも日額 $10 強かかる**ため、停止/起動スクリプトの習慣化と予算アラートを
  [ガイド03](guide_03_cost_operation.md) で必ず設定してください。1週間以上使わない場合は
  フル削除(62分で再構築可能)の方が安上がりです。

順番に読み進めれば構築が完了するように書かれています。各ガイドのコマンドは
**プレースホルダーなしでコピー&ペースト実行できる**ことを方針とし、
環境ごとに異なる値は「確認コマンド → 環境変数に格納 → 以後は変数参照」の形をとります。
人間の選択が必要な箇所のみ `【】` で明示し、必ず選び方・確認手段を併記しています。

### 記載内容の検証水準

本ガイドの記載は次の3水準を区別しています。①**実測済み**: オレゴンでの実構築で
実行・確認した手順と数値(所要時間・コスト・トラブル対処・各種 ID/URL の確認コマンドを
含む。大半がこれ)。②**コード確認**: COA v0.1.0 のソースコードから導出した記述
(例: Cohere 利用時の疎通確認リクエスト形式。該当箇所に注記あり)。③**未検証**:
東京リージョン全般・フル削除(`make destroy-dev`)・IdP フェデレーション
(該当箇所に「未検証」と明記)。②③に該当する手順は、記載の検証コマンドで
動作を確認しながら進めてください。
